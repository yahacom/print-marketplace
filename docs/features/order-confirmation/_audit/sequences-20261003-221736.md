## Re-examined (requested explicitly, given the same-day sad.md/ADR revision)

- **Flow 1 (US-02, AC-01 — confirm happy path)** and **Flow 2 (US-03, AC-02 — decline happy path)**: found an asymmetry — flow 1's transaction step carried an "(abort if decision already set)" note that flow 2's did not, even though AC-04's invariant binds confirm and decline identically. Both flows also lacked a branch for the document not existing at all (a client could `POST confirm/decline` without first `GET`-ting the screen). Fixed: both flows now have a `document not found` branch (404, same messaging as flow 3) and an explicit, symmetric `Note` that the transaction re-checks `decision` is still unset before writing (closes the race between the initial `get()` and the transaction — ties directly to ADR-0007).
- Flows 3, 4, 5, 6: re-read against the current §5 Container view and ADR-0001–0008; no inconsistencies found. Left unchanged.
